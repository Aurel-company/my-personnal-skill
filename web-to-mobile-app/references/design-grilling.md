# Design grilling: question bank

Used at step 3. Ask one branch at a time, follow up on vague answers, and stop a branch only when the decision is unambiguous. Skip what the contract already answers.

## Identity
- Should the app feel like the web app, like the platform, or like a new product?
- Which existing brand elements are mandatory (logo, colors, typeface, illustrations, tone)?
- Three apps whose feel you want to be close to, and one you want to avoid. Why?
- Light, dark, or both? Is dark mode a requirement at launch?

## Platform stance
- Native look per platform, or one shared custom design? Where is each acceptable?
- System font (SF Pro, Roboto) or brand font? On which elements?
- System icons (SF Symbols, Material Symbols) or a custom set?

## Density and hierarchy
- What is the one thing a user must see in the first second on each core screen?
- Information-dense (pro tool) or airy (consumer)?
- How much text per card or row? Which fields are always visible?

## Interaction
- Which actions are primary on each core screen, and where do they live (bottom bar, floating button, navigation bar)?
- Which swipe actions, long-press menus and gestures do you want? Are any risky (destructive swipe)?
- Haptic feedback: where, and how much?
- Motion personality: calm and quick, or expressive?

## Content and states
- Real content lengths: longest name, title, number? Localization and right-to-left?
- Empty states: illustration, text only, or a call to action?
- Tone of error messages and confirmations?

## Accessibility
- Must the layout survive the largest Dynamic Type / font scale?
- Contrast target, color-blind safety, VoiceOver / TalkBack priorities?

## Scope of the artifact
Defaults for screens, sizes and formats: [design-artifact-guide.md](design-artifact-guide.md).
- Which screens first (usually the core tab roots and one detail)?
- Static mockups, clickable prototype, or both? iOS only, Android only, or side by side?
