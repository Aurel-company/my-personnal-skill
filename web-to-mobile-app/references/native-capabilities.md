# Native capabilities

Used at step 1, for the **Add** and **Replace** verdicts. One row per capability. Cost is judgment, relative to a cross-platform stack: **S** a library and a screen, **M** platform-specific code or a backend change, **L** native extensions, separate targets or new infrastructure. Platform rules change every year: check the official pages (see `sources.md`).

| Capability | User value | Add when | Cost | Permission | Pitfalls |
|------------|-----------|----------|------|------------|----------|
| Push notifications | Brings the user back at the right moment | The web app sends emails or has time-sensitive events (message, status change, reminder) | M (APNs, FCM, backend sender, deep links) | iOS: authorization prompt (provisional possible); Android 13+: `POST_NOTIFICATIONS` | Asking at first launch gets refused; too many pushes → disabled; Android channels per category; every push must deep link somewhere useful |
| Biometrics | Unlock in one glance instead of typing a password | Users log in often, or the app holds sensitive data | S | iOS: `NSFaceIDUsageDescription`; Android: none (BiometricPrompt) | Protects a stored token, it is not an identity; always offer a fallback; re-enroll on biometric change |
| Passkeys | Phishing-resistant login without password | The web app already supports or plans WebAuthn | M (server WebAuthn, associated domains) | None | Needs `webcredentials` (iOS) and Digital Asset Links (Android) on the domain; keep account recovery |
| Camera | Capture instead of upload | A feature takes photos or video (receipts, proofs, profile) | S | iOS: `NSCameraUsageDescription`; Android: `CAMERA` (not needed through the system camera intent) | Purpose string must be specific or review rejects it; handle denial with a library fallback |
| Document scanner | Clean, cropped multi-page scans | A feature uploads paper documents | S (VisionKit, ML Kit Document Scanner) | iOS: camera; Android ML Kit scanner: none | ML Kit scanner needs Google Play services; output is image or PDF, check backend formats |
| Photo library | Pick images without file browsing | A feature uploads images | S | None with the system pickers (PHPicker, Android Photo Picker); full library access needs a permission | Ask for full access only if the app truly browses the library; iOS limited access must be handled |
| Location, one-off | Prefill address, nearby results | A form asks for an address or a list depends on distance | S | When-in-use (iOS), `ACCESS_COARSE/FINE_LOCATION` (Android) | Offer manual entry; request coarse when enough |
| Location, background | Geofence alerts, trip tracking | The core value depends on where the user is while the app is closed | L | iOS: "Always", asked after when-in-use; Android 10+: `ACCESS_BACKGROUND_LOCATION`, separate request (11+) | Battery; strict store review and Play declaration; privacy label; rejected without a visible user-facing reason |
| Widgets | Glanceable data without opening the app | One number, status or short list is checked several times a day | M to L (WidgetKit extension in Swift; Android Glance / App Widgets) | None | Refresh budget limited, not real time; separate target; data shared via app group / storage |
| Live Activities / ongoing notifications | Follow a live event on the lock screen | A task lasts minutes to hours with progress (delivery, ride, timer, match) | L (ActivityKit extension, push updates) | iOS: Live Activities can be disabled by the user; Android: notification permission | iOS: limited duration (about 8 h active); Android: ongoing notification or foreground service, Live Updates on Android 16+ (verify) |
| Quick actions and shortcuts | Jump to a task from the icon or Siri / Assistant | 2 to 4 frequent tasks start from scratch (new item, scan, search) | S (static), M (dynamic, App Intents) | None | Each must deep link to a screen that handles cold start |
| Share out | Send content to any app | The web app has "copy link", export or send by email | S | None | Share a URL that opens the app (universal / app link) with a web fallback |
| Share in | Receive content from other apps | Users bring photos, links, files or text into the product | M (iOS share extension, Android intent filters) | None | Separate iOS extension with memory limits; user may be logged out in the extension |
| Haptics | Confirms actions without looking | Success, error, selection, destructive confirmation, drag snap | S | None (Android `VIBRATE` is a normal permission) | Overuse is noise; follow system patterns; respect system settings |
| Contacts | Invite or pick people without typing | Invite, share or assign to people outside the app | S to M | iOS: contacts (limited access from iOS 18); Android: `READ_CONTACTS` | Prefer the system contact picker (no permission); never upload the address book without explicit consent |
| Calendar | Add events in one tap | The product has bookings, deadlines or events | S | iOS 17+: write-only access is enough to add; Android: none through the insert intent | Do not request full read access to add one event |
| NFC | Tap to read or write a tag or card | Physical objects are identified (inventory, access, tickets) | M | iOS: Core NFC entitlement; Android: `NFC` | Device coverage varies; iOS tag writing and background reading are limited; test on hardware |
| Native payment (Apple Pay / Google Pay) | Pay without typing a card | The app sells **physical** goods or services used outside the app | M (payment provider support, merchant setup) | None | Digital goods and features consumed in the app must use App Store / Play billing; check the current rules per region |

## Choosing

Judgment: add at most 2 or 3 capabilities to the first release, those that replace a web friction already present (email → push, upload → camera or scanner, password → biometrics or passkeys). Put the rest in wave 3 or in open decisions.
